# AISubs: восстановление дорежимного лендинга

## Решение

Восстановить GitHub Pages из состояния непосредственно перед редизайном,
который начал отдельно объяснять Auto и Manual. Источником служит
`docs/index.html` из коммита `1637010` (Git blob
`faacabe6550501b5058eb3b93af3971862ea5699`). Это тот же файл, который находился
в `7c6978d^`.

Текущий краткий технический лендинг не теряется: он зафиксирован в коммите
`2a84e59` и может быть восстановлен из истории Git.

## Пользовательский результат

Посетитель снова видит прежнюю продуктовую страницу AISubs без отдельного
объяснения режимов. Страница последовательно отвечает на вопросы:

1. Что такое AISubs и какой результат он создаёт.
2. Что приложение умеет.
3. Из каких частей состоит интерфейс.
4. Как настраивается типографика субтитров.
5. Как устроена локальная обработка.
6. Как установить приложение и какие есть требования.

## Информационная структура

Восстанавливаются исходные разделы и их порядок:

- вводный экран AISubs со ссылкой на GitHub;
- демонстрация продукта;
- «Что умеет»;
- «Интерфейс по частям»;
- «Типографика без ручной правки»;
- «Как всё устроено»;
- «Установка»;
- «Требования»;
- компактный подвал.

Блоки «Режимы обработки», сравнение Auto/Manual и более поздняя техническая
компоновка не переносятся. Само приложение и его режимы не изменяются.

## Допустимое отличие от исторической версии

Единственное содержательное дополнение — небольшая ссылка
`@daipotestit` в подвале. Она ведёт на `https://t.me/daipotestit`, не становится
главным CTA и не меняет композицию основных разделов.

Актуальные ссылки на репозиторий `jimmorisedu-boop/aisubs-local` сохраняются.

## Файлы и совместимость

- `docs/index.html` восстанавливается из указанного исторического состояния и
  получает минимальное дополнение в подвале.
- `docs/tokens.css` и `docs/landing.css` не подключаются старой автономной
  страницей. Их не требуется удалять в рамках восстановления.
- Продуктовый код, README, установщик, скриншоты и документация приложения не
  изменяются.
- `tests/test_public_presence.py` корректируется только там, где его проверки
  описывают более позднюю структуру лендинга.

## Доступность и адаптивность

Историческая разметка должна остаться работоспособной на ширинах 320, 375, 414,
768 и 1280 пикселей. Перед публикацией проверяются:

- отсутствие горизонтальной прокрутки;
- читаемость текста и изображений;
- клавиатурный фокус на ссылках;
- содержательные альтернативные подписи изображений;
- доступность GitHub и Telegram-ссылок с клавиатуры.

Исправления допускаются только для явных дефектов доступности или поломки на
современном браузере; они не должны менять запомнившуюся структуру и подачу.

## Проверка результата

- `docs/index.html` основан на blob `faacabe6`, за исключением минимальной ссылки
  на канал и подтверждённых исправлений доступности.
- На странице присутствуют все семь восстановленных содержательных разделов.
- Отсутствуют отдельный блок режимов и таблица Auto/Manual.
- GitHub-ссылки и `https://t.me/daipotestit` корректны.
- Все локальные изображения страницы существуют.
- Тесты публичной страницы и полный релевантный набор тестов проходят.
- Страница визуально проверена на обязательных desktop/mobile ширинах.
- GitHub Pages успешно публикуется из `main:/docs`.

## Вне объёма

- Изменение логики Auto или Manual.
- Изменение удобства пакетной обработки.
- Переписывание README и остальных документов.
- Новый маркетинговый текст или новый визуальный редизайн.
- Удаление текущего технического варианта из истории Git.
