# AISubs: краткий технический лендинг

## Цель

Заменить рекламную подачу GitHub Pages на компактную техническую страницу,
по которой видеомонтажёр или небольшая студия за 1–2 минуты понимает:

- что делает AISubs;
- чем отличаются Auto и Manual;
- на каком оборудовании приложение работает;
- как его установить и запустить;
- где находится подробная документация.

Страница не должна дублировать README и не должна обещать неподтверждённые
выгоды, скорость или качество распознавания.

## Тон и принципы

- Тон: технический, утилитарный, спокойный.
- Формулировки описывают функции и ограничения, а не продают продукт.
- Используются только подтверждённые репозиторием характеристики.
- Auto остаётся первым и самым коротким пакетным сценарием.
- Manual описывается как дополнительный контроль перед рендером, а не как
  обязательный этап.
- Тёмная палитра приложения и один сине-фиолетовый акцент сохраняются.
- Анимации и декоративные иллюстрации не добавляются.

## Информационная структура

Страница занимает примерно 2–3 экрана на настольном компьютере и состоит из
четырёх компактных частей.

### 1. Заголовок и назначение

- Название `AISubs` без рекламного слогана.
- Одно предложение: локальное Windows-приложение для пакетного создания
  субтитров с режимами Auto и Manual.
- Небольшая строка фактов: Windows 10/11, локальная обработка, CPU/CUDA,
  `faster-whisper` и `ffmpeg`.
- Три ссылки без повторов: GitHub, установка в README, `@daipotestit`.
- Один актуальный скриншот реального интерфейса; без декоративной рамки
  браузера или имитации окна.

### 2. Auto и Manual

Одна компактная сравнительная таблица:

| Режим | Назначение | Процесс |
| --- | --- | --- |
| Auto | Обработка пакета без промежуточной проверки | Добавить файлы → запустить → получить результаты |
| Manual | Проверка текста и таймингов до пакетного рендера | Распознать → проверить/одобрить → отрендерить одобренное |

Таблица заменяет две рекламные карточки и отдельный блок workflow. На мобильном
экране строки превращаются в две читаемые вертикальные секции без горизонтальной
прокрутки.

### 3. Технические характеристики

Короткий definition list или двухколоночная таблица:

- ОС: Windows 10/11, 64-bit;
- распознавание: `faster-whisper`, пословные таймкоды;
- вычисления: NVIDIA CUDA при наличии, CPU fallback;
- видео: обработка и рендер через локальный `ffmpeg`;
- данные: исходники, транскрипты, кэш и результаты остаются на компьютере;
- состояние: Manual-черновики и ревизии восстанавливаются с диска;
- результаты: существующие файлы не перезаписываются молча.

Перечень поддерживаемых контейнеров не публикуется без отдельной проверки
реальных ограничений загрузчика и `ffmpeg`-команд.

### 4. Установка

- Две команды: `setup.bat` и `run.bat`.
- Одно пояснение: установщик разворачивает портативный Python, `ffmpeg` и
  зависимости; сеть требуется для установки и первой загрузки модели.
- Ссылка на полную инструкцию в README.
- Компактный footer: GitHub, README, MIT, `@daipotestit`.

## Визуальная система

- Структура ближе к технической справке, чем к маркетинговому лендингу.
- Максимальная ширина текста ограничена для удобного чтения.
- Заголовок обычный, без огромной плакатной типографики.
- Секции разделяются тонкими линиями и отступами, а не карточками и тенями.
- Акцентный цвет используется только для ссылок, фокуса и активных элементов.
- Скриншот — единственный крупный визуальный объект.
- Все цвета, шрифты, интервалы, радиусы и состояния ссылок задаются токенами.

## Навигация и взаимодействия

- Верхняя навигация содержит только название и ссылки на GitHub/README.
- Внутренняя якорная навигация не нужна: страница короткая.
- Нет вкладок, раскрывающихся блоков, каруселей и JavaScript-зависимостей.
- Ссылки имеют `hover`, `focus-visible`, `active` и посещённое состояние;
  отключённые, loading, error и success состояния неприменимы, поскольку
  страница не содержит форм или асинхронных действий.

## Адаптивность и доступность

- Проверяем ширины 320, 375, 414, 768 и 1280 пикселей.
- Горизонтальная прокрутка отсутствует.
- Кликабельные подписи не переносятся на две строки.
- Таблица Auto/Manual становится вертикальной на узких экранах.
- Скриншот имеет содержательный `alt`.
- Сохраняются семантические `header`, `main`, `section`, `table`/`dl`, `footer`.
- Фокус-кольцо контрастное и появляется без анимации.
- Цвет не является единственным способом различить режимы.

## Изменяемые файлы

- `docs/index.html` — новая компактная разметка и подключение стилей.
- `docs/tokens.css` — токены страницы.
- `docs/landing.css` — компоновка, типографика и адаптивные правила.
- `.hallmark/log.json` — запись о новом варианте структуры.
- `tests/test_public_presence.py` — обновлённый контракт GitHub Pages.

Удаления производственных файлов не требуется. README, приложение, скриншоты
и логика Auto/Manual не изменяются.

## Проверка

- HTML содержит фактическое описание, Auto/Manual, системные требования,
  команды запуска и все четыре внешние ссылки.
- Старые рекламные фразы и повторяющиеся CTA отсутствуют.
- Все локальные CSS и изображения существуют и доступны из `/docs`.
- Python-тесты публичного присутствия проходят.
- В браузере проверены desktop и все четыре обязательные мобильные ширины.
- GitHub Pages успешно собирается из `main:/docs`.

## Вне объёма

- Изменения интерфейса приложения.
- Изменения README и установщика.
- Новые сборки или GitHub Releases.
- Аналитика, формы, загрузки и интерактивная демонстрация.
- Английская версия страницы.
